# Evidencia 06: Manejo de errores controlados en la API (404, 422, 400)
Fecha y hora: 2026-10-22T20:27:19-05:00
Qué se probaba: Que la API devuelva códigos HTTP claros y mensajes explicativos ante entradas inválidas o reglas del negocio incumplidas, sin corromper la base de datos ni caer el servidor.
Comandos ejecutados:
  1. Servicio inexistente -> POST /citas con servicio='acupuntura_laser' (HTTP 422)
  2. Código de cita inexistente -> GET /citas/VF-NOEXISTE99 (HTTP 404)
  3. Fecha en el pasado -> POST /citas con fecha='2020-05-10' (HTTP 422)
  4. Hora fuera del horario de la clínica -> POST /citas con hora='21:00' (HTTP 422)
  5. Cuerpo incompleto / sin confirmación -> POST /citas con confirmado=false (HTTP 422)
  6. Intentar reprogramar una cita ya cancelada (VF-1E8A68B1F8) -> PATCH /citas/VF-1E8A68B1F8/reprogramar (HTTP 400)
